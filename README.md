> 赛季：2026.11 — 2027.08

## 这个仓库是什么

参赛作品的**全部工程过程**都放在这里：规则解读、方案文档、结构图纸、电路、固件、测试数据、决策记录。

第二十二届规则明确要求参赛队在 Gitee 建立开发者账号并托管开发过程，作品视频与开发管理文件会接受 AI 查重与溯源。因此这个仓库不只是"存代码的地方"，它本身是**参赛材料的一部分**。提交历史要有真实的演进痕迹：初版图纸、第一次点亮、失败的尝试、参数整定的过程，都值得留。

## 提交规范

提交信息用中文，一行说清"做了什么"，必要时补一行"为什么"。

```
结构：完成球壳法兰对接件 v1，壁厚 3mm
固件：驱动轮速度环跑通，阶跃超调 18%
实验：透明壳遮挡信标，5 次全部未触发 -> 需加遮光环
```

约定：

- 一次提交只做一件事，不把"改结构 + 调参数 + 改文档"混在一起
- 重要节点打 tag，如 `proto-01`、`pcb-v1`、`race-ready`
- 大文件（视频、STL、安装包）不要直接提交，放网盘并在文档里留链接

## 合规备忘

这几条不满足会直接影响成绩，逐条对照：

- [ ] 自制 PCB 在正面覆铜层标注**学校 / 队伍 / 年份**，丝印层含**制作文件二维码**
- [ ] PCB 通过嘉立创大赛指定通道下单（免费）
- [ ] 车模留**标准发车接口**，按《竞赛车模发车硬件和软件协议》实现，支持硬件切断
- [ ] 不使用带 MCU 的智能传感器，不使用"智能车专用"成品模块
- [ ] 最小系统板只含 MCU / 时钟 / 电源 / 调试接口，外设一律经自制主板引出
- [ ] 全过程在本仓库留痕，关键节点有提交记录

## 远端仓库

**主远端（origin）**

```
https://github.com/Octidote/smartcar-2027
```

推送：`git push`（凭据由 GitHub CLI 托管，不需要输密码）

**Gitee 镜像（暂未接入）**

竞赛官方要求托管在 Gitee，评审看的是 Gitee。当前只在 GitHub 上维护，Gitee 侧尚未接入推送。

后续接入有两条路：

```bash
# 方案一：给 origin 挂第二个 push 地址，一条命令推两边
git remote set-url --add --push origin https://github.com/Octidote/smartcar-2027.git
git remote set-url --add --push origin https://gitee.com/eight-detoxifiers/smartcar-2027.git

# 方案二：单独加一个 gitee 远端，需要时手动推
git remote add gitee https://gitee.com/eight-detoxifiers/smartcar-2027.git
git push gitee main
```

> 注意：方案一里 Gitee 未认证时会导致每次 `git push` 都报错（GitHub 仍会成功）。认证一次之后就没问题了。

> 竞赛要求的是**开发过程留痕**，所以不要等"做完再传"。从现在开始，每次有实质进展就提交一次。
